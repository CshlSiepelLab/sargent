# SARGENT: Current Status and Roadmap

*Last updated: 2026-05-15*

## Model overview

SARGENT fits the linear mixed model

    y = X β + u + ε,   ε ~ N(0, σ²I),   u ~ N(0, Σ_s w_s² G_s)

where X β is a BayesR sparse fixed-effects component and the covariance of u
is a weighted sum of local-tree kinship matrices G_s from the ARG.  Inference
is done in two stages:

- **Stage 1** (`var_fixed`): variational BayesR coordinate descent for β and σ²
  with V = σ²I (fixed effects only).
- **Stage 2** (`var_random`): REML EM updates for the segment weights w_s² and
  σ², using CG solves for V⁻¹ and Hutchinson stochastic trace estimation for
  tr(V⁻¹ G_s).

## Stage 1 (fixed effects) — working

### What was fixed

| Issue | Fix |
|-------|-----|
| `simulate.py` used raw dosages (0/1/2) to compute y_fixed, giving phenotypes with mean ≈ 2·MAF | Switched to standardized genotypes (zero-mean, unit-variance) in the simulator |
| SARGENT did not center phenotypes before inference | Added mean subtraction in `sargent_new` |
| Convergence used `max_delta < 1e-6` (never met with p >> n) | Changed to relative σ² change `rel_dsig < 1e-4` |

### Evaluation on simulated data

**Dataset:** `fixed_clean.*` (generated by `scripts/simulate.py`, seed 7)

| Parameter | Value |
|-----------|-------|
| n individuals | 200 |
| p SNPs | 24 |
| S trees | 27 |
| n_causal (non-null β) | 1 (snp 16, β = −0.707) |
| True h²_fixed (realized) | 0.565 |
| True σ² | 0.500 |

**Results:**

| Quantity | True | Estimated | Notes |
|----------|------|-----------|-------|
| h²_fixed | 0.565 | 0.463 | ~18% underestimate; expected BayesR shrinkage |
| σ² | 0.500 | 0.475 | ~5% underestimate |
| Causal SNP rank | — | #1 | correctly identified as top hit |
| Iterations to convergence | — | 14 | fast |

The algorithm is algorithmically correct.  The ~18% h² underestimate reflects
prior misspecification: the true β = 0.71 is 7× the prior SD (σ_mix[3] = 0.1),
so the posterior shrinks toward zero.  This is expected BayesR behavior, not a
bug.

### Known limitations / future work (Stage 1)

1. **Prior calibration.** The sigma2_mix grid [0, 1e-4, 1e-3, 1e-2]·Var(y) is
   calibrated for many small effects.  For simulations where the few causal
   effects are drawn from this grid and then rescaled to hit a target h²,
   the rescaled betas can far exceed the prior SD, causing heavy shrinkage.
   *Future:* expose sigma2_mix as a user option; add an empirical-Bayes warm
   start that estimates effect-size scale from the data before the VB sweep.

2. **Slow convergence with p >> n.** BayesR coordinate descent converges
   geometrically in the p >> n regime, but many SNPs make tiny residual
   adjustments that keep max_delta > threshold.  The sigma2-based convergence
   criterion addresses this for most cases, but the convergence constant
   is proportional to max(eigenvalue of X^T X / n), which grows with p/n.

3. **Posterior variance term missing from σ² update.** The current update
   σ² = ‖r‖²/n is biased when posterior variances E[β_j²] − (E[β_j])² are
   non-negligible.  The correct EM update adds Σ_j v_jk·γ_jk to the
   numerator.  Effect is small for sparse solutions but may matter for
   dense signals.

## Stage 2 (random effects) — broken, fundamental issue

### What was fixed (convergence infrastructure)

- Dense Cholesky path removed (was 3–4× slower than CG due to O(S·n) column
  fills vs O(k_CG·S·n) CG cost with k_CG ≈ 5).
- Early-exit bug fixed: the `iter >= 1` guard prevents immediate convergence
  on iteration 0 when ws2 = 0 gives rel_change = 0.
- ws2 removed from convergence check (Hutchinson noise floor ~3% makes
  max_rel_ws2 < 1e-4 unachievable).
- σ²-only convergence criterion retained.

### The per-tree signal collapse problem

**Dataset:** `rand_clean.*` (n=100, S=971 trees, h²_random = 0.66, σ² = 0.40)

After 15 iterations: h²_rand = 0.24 (true = 0.66), σ² = 0.69 (true = 0.40).
The mixture weights φ barely move from the uniform prior.

The mixture update for rho_{sm} uses the score

    score_m = τ²_m · 0.5 · (A_s − B_s)

where A_s = r̃ᵀ G_s r̃ and B_s = tr(V⁻¹ G_s).  The expected value of
A_s − B_s for a tree with true w_s² > 0 is approximately

    E[A_s − B_s] ≈ w_s^{true} · tr(G_s²) / σ²²

The prior is calibrated as τ²_mix[3] = Var(y) / (S · gscale), so

    score_m ≈ τ²_mix[3] · w_s^{true} · tr(G_s²) / σ⁴
            ∝ h²·Var(y)² · n / S²

**For S = 971, n = 100:** score ≈ 3.5×10⁻³ per iteration.  The softmax
exp(3.5e-3) − 1 ≈ 3.5e-3, so rho changes by < 0.4% per sweep.  At this rate,
the mixture would need ~1000 iterations to converge.

**For S = 20, n = 100:** score ≈ 3.3 — O(1), mixture converges quickly.

This is the **1/S² score collapse**: because τ²_mix[m] ∝ 1/S and the
per-tree signal (A_s − B_s) also scales as ~1/S (each tree explains only 1/S
of h²_rand), the product collapses as 1/S².  As a result:

- σ² converges to Var(y) · (1 − φ[3]) ≈ 0.75 · Var(y) instead of 0.40.
- The mixture never identifies which trees have large vs small weights.

### Options for fixing Stage 2

#### Option A: Tree pruning / coarsening (recommended first step)

Merge adjacent trees that differ by only one or a few SPR operations into a
single representative segment.  This reduces S from ~1000 to ~50–100 while
preserving the dominant variance-structure information.

- Directly eliminates the 1/S² collapse.
- Leaves the existing scoring and EM architecture intact.
- A simple pruning heuristic: merge any two adjacent trees whose Robinson–
  Foulds distance is zero (identical topologies); optionally also merge trees
  with RF distance 1 or 2.
- tskit provides efficient tree-by-tree iteration; merging can be done as a
  pre-processing pass over the `.trees` file.

#### Option B: Spike-and-slab with scalar scale parameter

Replace the M=4 discrete mixture with a two-component spike-and-slab:

    w_s² | z_s ~ z_s · Gamma(α, β) + (1 − z_s) · δ₀,   z_s | φ ~ Bernoulli(φ)

Jointly estimate (φ, α, β) by EM.  Benefits:

- The Gamma scale parameter β can be inferred from the data, adapting to the
  actual signal level without requiring the 1/S calibration.
- A single global φ and scale (α, β) replace S independent mixture assignments,
  so the effective number of free parameters is small.
- The score driving the z_s update is still per-tree, but α and β provide a
  self-consistent scale that avoids the 1/S² collapse.

#### Option C: Smoothness penalty on adjacent w_s²

Add a Gaussian Markov random field prior on log(w_s²) that penalizes sharp
changes between adjacent trees.  This effectively pools evidence across nearby
segments, raising the local signal-to-noise ratio.

Computationally cheap to add as an augmented gradient; works within the
existing EM framework.

#### Option D: Score normalization / parameterization change

Instead of the raw τ²_mix[m] · (A_s − B_s) score, use a normalized form:

    score_m ← [τ²_mix[m] · A_s − (tr(G_s) / tr(V⁻¹))] / (noise std)

calibrated so that the score is O(1) per tree regardless of S.  This is
analogous to the z-score normalization used in Stage 1.  Requires careful
derivation from the ELBO or REML score, and validation against the per-tree
chi-squared distribution under the null.

### Recommended next steps for Stage 2 (convergence)

1. Implement Option A (tree pruning) as a pre-processing step in `sargent_new`
   or as a standalone tskit pass.  Validate that reducing S from ~1000 to ~50
   makes the mixture converge in ~20 iterations on `rand_clean.*`.
2. Once convergence is demonstrated on pruned trees, evaluate whether the
   pruning loses meaningful statistical signal (compare h² estimates before and
   after pruning on a range of simulations).
3. Consider Option B (spike-and-slab) as a cleaner long-term replacement for
   the M=4 fixed-grid mixture.
4. For the large-S regime without pruning, Option D (score normalization) is
   the theoretically cleanest fix and does not require changing the tree
   representation.

### Stage 2 efficiency: future optimizations (from `stage2_optimization.md`)

Fix 1 (reuse Hutchinson probes across segments) is already implemented: each
outer iteration solves V z_k = ε_k once per probe and reuses the z_k vectors
for all S segments, reducing CG solves from O(S · N_probe) to O(N_probe).
Three further optimizations remain worth pursuing:

#### Fix 2: Incremental tree-sequence MVPs

For S in the millions (genome-wide analyses), even the O(S · N_probe · n) cost
of Fix 1 is significant because each G_s-MVP is currently computed from scratch
by a full post-order traversal of tree s.

Adjacent local trees in a tree sequence differ by a small number of SPR-like
edge edits.  The full sequence of products {G_s v}_{s=1}^S can therefore be
computed incrementally in O(T · n) time, where T is the total number of
distinct edges across the tree sequence — sub-linear in S for typical ARGs.
Lee et al. (2025) and Zhu et al. (2026) implement this strategy.

The current SARGENT code iterates trees independently (one post-order traversal
per tree per vector); switching to the incremental form requires tracking which
edges are added/removed at each recombination breakpoint and updating the
running accumulator rather than restarting.  This is the main scalability
bottleneck for biobank-scale (S ~ 10⁶) use and should be pursued after Fix 3
is validated.

#### Fix 3: Constant-B̄ approximation (analog of ū for SNPs)

In the polygenic regime V ≈ cI, so B_s ≈ tr(G_s)/c.  More generally,
B_s / tr(G_s) is approximately constant across segments.

Calibration procedure (mirrors the ū calibration for u_j):

1. Sample ~30 calibration segments.
2. Compute each B_s exactly via the Hutchinson estimator.
3. Fit the scalar ratio B̄ = mean(B_s / tr(G_s)) across calibration segments.
4. Approximate B_s ≈ B̄ · tr(G_s) for all remaining segments.

Since tr(G_s) = Σ_i G_s[i,i] is O(n) to compute (just the diagonal of the
kinship matrix, which follows from summing squared branch-length contributions
at each leaf), this replaces N_probe G_s-MVPs per segment with a single O(n)
diagonal pass.  This matters when S is large enough that the O(S · N_probe · n)
MVP cost of Fix 1 is still a bottleneck.

Validation: plot exact vs. B̄·tr(G_s) approximated B_s values on a real
simulation before deploying; empirically verify that the approximation does
not degrade h² estimates.

#### Fix 4: Stochastic and lazy updates

Most w_s² will sit in the null mixture component and contribute little signal.
Two complementary strategies reduce the work spent on those segments:

- **Mini-batch updates.** On each outer iteration sample a random subset of
  segments (e.g., 10–20%) and update only those ρ_sm.  This is standard
  stochastic coordinate ascent and converges to the same fixed point; similar
  to mini-batch EM in topic models.
- **Lazy refresh.** Track the last iteration at which each segment's ρ_sm
  changed materially (e.g., max component change > 1%).  For segments that
  have been stuck in the null for ≥ k iterations, skip the B_s recomputation
  until they get selected by mini-batch sampling.

Both approaches are straightforward to implement once Fix 3 is in place
(lazy refresh is most valuable when per-segment B_s is expensive to compute).

**Implementation order:** Fix 3 first (low risk, large speedup for large S);
Fix 2 next for biobank-scale S (requires tree-sequence edge-diff bookkeeping);
Fix 4 last if profiling shows stochastic updates are still needed.
